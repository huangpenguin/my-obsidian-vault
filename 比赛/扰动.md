官方 [LIBERO-Plus 论文](https://sylvestf.github.io/LIBERO-plus/) 将具身智能模型的脆弱性归结为 **7 大维度**（包含 21 个子组件）的扰动。而在社区恢复的数据集（如你使用的 5 大分类）中，这 7 类扰动被进一步收拢映射。

## 一、 LIBERO-Plus 到底有哪些扰动？

|官方 7 大扰动维度|对应社区 5 大 Category|具体扰动表现形式|
|---|---|---|
|**1. Objects Layout (物体布局)**|`env`|物体初始放置位置/角度随机偏移，引入无关干扰物（Distractors）。|
|**2. Camera Viewpoints (相机视角)**|`camera_pose`|相机外参（位置、仰角、旋转角）及视场角（FOV）发生偏差。|
|**3. Robot Initial States (机器人状态)**|`sensor_noise` / `env`|机械臂启动时的初始关节角（Joints）或末端位姿存在抖动。|
|**4. Language Instructions (语言指令)**|`language`|同义词替换、句式重写、上下文扩展、增加无用干扰描述。|
|**5. Light Conditions (光照条件)**|`lighting`|改变环境光漫反射颜色、光源位置/方向、高光强度与阴影。|
|**6. Background Textures (背景纹理)**|`env`|替换桌面、墙壁、周边物体的贴图、材质与色彩。|
|**7. Sensor Noise (传感器噪声)**|`sensor_noise`|在图像帧中注入像素级高斯噪声、色彩抖动或控制时延。|

## 二、 训练前处理（Data Pipeline / Preprocessing）有哪些可实现的方案？

利用现有的 14k 轨迹和已恢复的 `episode_perturbation_map.csv` 标签，可以在**数据预处理、数据增强与 Sampler 构造**阶段采取以下策略：

### 1. 视觉数据增强（针对 `lighting` / `env` / `camera_pose` / `sensor_noise`）

直接在 DataLoader 提取图像帧时，施加轻量级的图像变幻，提升模型在视觉维度的隐式不变性：

- **针对 Light & Background (`lighting` / `env`)**：
    
    - **ColorJitter**：随机调整图像的 `Brightness`（亮度 ±0.2）、`Contrast`（对比度 ±0.2）、`Saturation`（饱和度 ±0.2）。
        
    - **Random Channel Swap / Grayscale**：以小概率（如 5%）将 RGB 转为灰度或抖动通道，削弱策略对色彩过拟合的依赖。
        
- **针对 Camera Pose & Layout (`camera_pose` / `env`)**：
    
    - **Random Spatial Crop & Resize**：对 224×224 的输入进行轻微随机裁剪（如 Crop 90%~100% 区域后 Resize 恢复），模拟相机外参的极小微移。_（注：平移幅度切勿过大，否则会导致动作 Action 标注与图像空间解耦）_。
        
- **针对 Sensor Noise (`sensor_noise`)**：
    
    - **Gaussian Noise & Cutout**：在图像张量上随机叠加标准差较小的高斯噪声，或添加随机小方块遮挡（Cutout / Random Erasing），增强抗噪和抗遮挡能力。
        
- **多视角条件处理（Multi-view Fusion）**：
    
    - **强化手腕相机（Wrist View）特征**：在输入模组中对 `wrist_rgb` 与 `agentview_rgb` 进行独立编码，提升手腕视角在 Attention 机制中的权重，利用手腕视角抵抗视角和背景扰动。
        

---

### 2. 本体感知与状态预处理（针对 `sensor_noise` / Robot Initial State）

- **State Noise Injection（状态噪声注入）**： 在训练读取 `observation.state`（关节角或末端位姿）时，加上极小的高斯噪声 N(0,σ2)。这能有效缓解模型因为初始关节角稍微偏离标准位置而导致的执行失败。  
    
- **State Normalization（状态标准化）**： 计算 14k 数据集中所有 `state` 的 Min/Max 或 Mean/Std，并在前处理阶段做全局标准化缩放，防止关节角量纲差异干扰网络收敛。  
    

---

### 3. 语言文本前处理（针对 `language`）

- **Instruction Paraphrasing（指令改写扩展）**： 在 Dataset 内部建立一个同义词/句式映射表（如 `"put the mug in cabinet"` → `"place the cup inside the cupboard"`）。训练时随机替换为同义句，防止模型记住固定的 Token 序列。
    
- **Language Instruction Dropout**： 论文发现 VLA 模型容易盲目忽略语言，沦为纯 Vision-Action 模型。在前处理阶段可以以 10%-15% 的概率把语言指令 Token **替换为空字符串** 或 **随机 Mask 部分名词**，强制模型学会利用视觉语义进行补全。  
    

---

### 4. 基于 `csv` 标签的批次采样与验证切分策略

利用已生成的 `episode_perturbation_map.csv`：

1. **Balanced Batch Sampling（均衡批次采样）**： 编写自定义 `BatchSampler`，确保每个 Training Batch 内部按比例（如各 20%）均衡混合 `env`、`lighting`、`language`、`camera_pose`、`sensor_noise` 这 5 类数据，避免梯度被单一种类的扰动或简单场景支配。
    
2. **Strict Stratified Split（严格防泄露切分）**： 划分 Train / Val 集时，**绝对不能按 Episode 随机切分**，而要按 `source_file`（基座任务）做 Group Split。确保 Val 集里的场景在 Train 集里从来没有出现过，才能真实评估泛化能力。
    



### 一、 第一阶段需着重应对的 3 大核心扰动

由于 Track 1 限定在“同一域和同一任务”，你可以**暂时放低**对“相机视角大范围偏移（Camera Pose）”或“全新语言指令（Language）”的优先级，集中精力攻克 **视觉外观层面的扰动**：

#### 1. 桌面与场景背景纹理扰动 (Texture & Surface Shift)

- **表现形式**：桌面从默认颜色被替换为大理石、木纹、不锈钢、高对比度花纹或纯色背景；墙壁/周边环境贴图改变。
    
- **致命影响**：视觉 Encoder（如未经特别增强的 ResNet / CNN）极易过拟合在背景纹理特征上。背景一换，模型的 Attention 注意力机制直接漂移到桌面上，导致机械臂找不到目标物体。
    

#### 2. 光照、高光与阴影变化 (Lighting & Shadows)

- **表现形式**：环境光照变暗/变亮、色彩偏黄/偏蓝、产生强烈的镜面高光反射（Specular Reflection）或物体投影。
    
- **致命影响**：高光反射会遮挡物体的关键边缘和关键点（Keypoints），导致末端执行器定位偏差；暗光则降低图像对比度，增加视觉感知的不确定性。
    

#### 3. 干扰物/目标物的外观与视觉噪声 (Object Appearance & Distractor Noise)

- **表现形式**：背景杂物（Distractor）的色彩/纹理变化，或图像被注入传感器高斯噪声/微小抖动。
    
- **致命影响**：如果模型依赖颜色去定位物体（如“抓红杯子”），当干扰物出现相似颜色或纹理变化时，策略容易被诱导走向错误方向。

### 二、 结合评价指标的针对性解题策略

预选赛不仅看 **Success Rate（成功率）**，还严格引入了 **平滑性（Jerk/SPARC）**、**效率（步数/距离）** 与 **安全性（碰撞）**。

#### 1. 如何提高 Success Rate（成功率）？

- **数据层面**：从你的 14k 数据集中，优先提取 **`env`（环境/纹理）** 和 **`lighting`（光照）** 这两个 Category 的轨迹做重采样训练。
    
- **视觉 BackBone 选型**：尽量选用对纹理不敏感、对结构和语义敏感的预训练 Encoder。
    
    - 推荐使用 **DINOv2** 或 **CLIP** 视觉特征（对光照和纹理变换有天然强鲁棒性），尽量避免从头训练简单的 CNN。
        
- **充分利用手腕视角（Wrist View）**：手腕相机的视野大部分被目标物体占据，受桌面和背景大面积纹理漂移的影响远小于主视角（Agent View）。
    

#### 2. 如何优化 Smoothness（加加速度 Jerk / SPARC）与 Safety（碰撞判定）？

- **为什么纹理扰动会导致 Jerk 变大？**
    
    当视觉受纹理/光照干扰时，模型预测出的 Action 序列会在相邻帧之间发生**严重剧烈抖动**（一会儿偏左一会儿偏右），这会导致 Jerk（加加速度）和 SPARC 指标暴跌，甚至在试探过程中撞击桌面或干扰物。
    
- **解法 1：使用 Action Chunking（动作块预测）**
    
    - 采用 **Diffusion Policy** 或 **ACT (Action Chunking with Transformers)**，一次性预测未来 $N$ 步（如 8-16 步）的动作序列。
        
    - 结合 **Temporal Ensembling（时序平滑加权）**，对重叠帧的动作取加权平均，能瞬间将 Jerk 和 SPARC 指标降低 50% 以上，同时显著减少轨迹总距离。
        
- **解法 2：低通滤波 / 动作空间平滑**
    
    - 在 Action 输出端增加低通滤波器（Low-pass Filter）或对机械臂末端执行器的旋转（EEF Rotation）加变化率限制，防止由于视觉噪声导致的突变动作。

### 三、 第一阶段实操 Check List（训练前处理与增强）

在训练 Data Pipeline 中，强烈建议开启以下针对性增强：

|**增强手段**|**参数/设置建议**|**针对的 Track 1 指标**|
|---|---|---|
|**ColorJitter**|Brightness $\pm 0.3$, Contrast $\pm 0.3$, Saturation $\pm 0.3$, Hue $\pm 0.1$|破除对特定光照与色彩的依赖 $\rightarrow$ 提升 Success Rate|
|**Random Cutout / Erasing**|随机遮挡 5%~10% 的区域|模拟高光反射/物体局部被遮挡 $\rightarrow$ 防止碰撞|
|**Random Channel Swap / Grayscale**|5%~10% 概率转为单通道/灰度|强制模型提取几何轮廓而非色彩纹理 $\rightarrow$ 提升泛化|
|**Action Temporal Smoothness**|动作块滑窗加权平均 (Temporal Ensembling)|直接优化 Jerk、SPARC 和 EEF 旋转总量 $\rightarrow$ 提升平滑性|

### 总结建议

在 Track 1 预选赛第一阶段：

1. **不要花精力在**：复杂语言指令解析、机械臂跨域迁移、大幅度视角旋转。
    
2. **重点放在**：利用 **DINOv2/强视觉增强** 搞定**纹理与光照**；利用 **Action Chunking / 平滑滤波** 搞定 **Jerk 和轨迹距离**。

# 全过程

## 创建VM

在GCP中创建相应的vm，注意区域可能有对机器spec的限制，然后磁盘的话是独立的，哪怕是系统盘也可以通过分离硬盘重新挂载而实现系统盘和系统的变更。

### インスタンスの立ち上げ

```markdown
#### イメージからインスタンスを作るとき（推奨）
1. Google cloud consoleのVMインスタンスタブから、「インスタンスを作成」をクリック。
2. 「マシンイメージからの新しいVMインスタンス」を選択
3. ty-standardイメージを選択。Continueをクリック。
4. デフォルトの設定のまま、インスタンスを作成。
5. このイメージは、docker, Nvidia-driver, nvidia-container-toolkitのセットアップが完了しているので、それらの設定は不要。Githubレポジトリのクローンのみ必要。

#### ゼロからインスタンスを作るとき
1. Google cloud consoleのVMインスタンスタブから、「インスタンスを作成」をクリック。
2. 以下の設定でインスタンスを作成する.特記ない場合はデフォルト.
- 名前: ty-test
- リージョン: us-central1
- ゾーン: 指定なし
- マシンの構成: GPUタイプ NVIDIA T4, 1GPU, Series N1
- マシンタイプ: プリセット n1-standard-4
- ブートディスク: OS Ubuntu 20.04 LTS, サイズ 50GB
```

### インスタンスへSSH接続(通过 SSH 连接到 GCP VM)

为了获取权限（比如ssh）这一步很重要

```bash
(本机安装并配置了 Google Cloud SDK)。
brew cask install google-cloud-sdk

(ログイン)
gcloud auth login

(プロジェクトの設定)
gcloud config set project pjt-aks

ここまですると自動で秘密鍵・公開鍵の設定をしてくれてインスタンスにSSH接続できる。

gcloud compute ssh <username>@<instance name> --zone=<zone name> -- -L 11434:localhost:11434
gcloud compute ssh penguinpp@pjt-aks-huang --zone=us-central1-f -- -L 11434:localhost:11434 

尝试连接(本机-VM映射)
gcloud compute ssh pjt-aks-huang --project=pjt-aks --zone=us-central1-f --tunnel-through-iap -- -L 11434:localhost:11434
(如果设置了外面ip无法访问则需要添加下面的tag才行)
gcloud compute instances add-tags pjt-aks-huang-80gb --zone=us-central1-c \
--tags=iap-accessible-vm

(实际用例)
gcloud compute ssh pjt-aks-huang --project=pjt-aks --zone=us-central1-f --tunnel-through-iap -- -L 11434:localhost:11434

gcloud compute ssh pjt-aks-huang-80gb --project=pjt-aks --zone=us-central1-c --tunnel-through-iap -- -L 11435:localhost:11435

gcloud compute ssh pjt-aks-a100-80gb --project=pjt-aks --zone=us-central1-a --tunnel-through-iap -- -L 11436:localhost:11436

gcloud compute ssh ex-test-vm --project=pjt-aks --zone=us-central1-c --tunnel-through-iap -- -L 11434:localhost:11434    
```

### nvidia-container-toolkitのインストール
コンテナ内でGPUを使うには nvidia-container-toolkitが必要。

# 1. 添加 NVIDIA GPG 密钥
curl -fsSL https://nvidia.github.io/libnvidia-container/gpgkey \
    | sudo gpg --dearmor -o /usr/share/keyrings/nvidia-container-toolkit-keyring.gpg
    
# 2. 添加软件源（适用于 Ubuntu 20.04）
distribution=$(. /etc/os-release;echo $ID$VERSION_ID)  # 会是 ubuntu20.04
curl -s -L https://nvidia.github.io/libnvidia-container/stable/deb/nvidia-container-toolkit.list \
    | sed 's#deb https://#deb [signed-by=/usr/share/keyrings/nvidia-container-toolkit-keyring.gpg] https://#g'

# 3. 更新 apt 包列表
sudo apt-get update

# 4. 安装 nvidia-container-toolkit（它包含 nvidia-ctk 工具）
sudo apt-get install -y nvidia-container-toolkit

# 5. 配置 docker 使用 NVIDIA 运行时
sudo nvidia-ctk runtime configure --runtime=docker

# 6. 重启 Docker 使配置生效
sudo systemctl restart docker
```

## 部署和启用ollama容器

```markdown
1.启动了 Ollama 的服务容器(在你的 Ubuntu VM 上,注意这里只是将VM-docker container的端口打通了)
sudo docker run -d --gpus=all -v ollama:/root/.ollama -p 11436:11436 --name ollama ollama/ollama:latest

(如果临时挂载新的disk):  sudo mount /dev/sdc1 /mnt
(对于一个已经存在上次未删除的容器)sudo docker start ollama

2.此时可以使用指令检查一下是否正常启动ollama容器
(检查容器状态) sudo docker ps -a | grep ollama
sudo docker ps

3.判断端口是否转发完成
(在gcp-cli;vm<->ollama)curl http://localhost:11434
Ollama is running
（在本地;local<->vm）E:\code\pjt-aks>curl http://localhost:11434
Ollama is running

4.在ssh中尝试使用Gemma模型：
sudo docker exec -it ollama ollama run gemma:7b
注意：如果之前已经下载过gemma:7b模型，这里会直接进入交互界面，无需重新下载。(ctrl+D退出)
远程拉取也是，如果已经有了就不需要下载了.

5.清理容器（完成后）：
sudo docker stop ollama  # 停止容器
sudo docker rm ollama   # 彻底删除容器（仅在需要时执行）

## 2. 什么是“并行运行” (Parallel Deployment)？

在 Azure Container Apps 中，并行运行通常意味着利用 **修订版本 (Revisions)** 功能：

- **旧版本 (Production)：** 正在跑的旧代码，处理正式的面试流量。
- **新版本 (New Revision)：** 你刚刚部署的代码。
- **并行逻辑：** 你可以设置流量比例（比如 90% 给旧版，10% 给你的新版），或者新旧版同时存在，通过不同的 URL 访问。

**为什么要这么做？**

- **安全性：** 万一你的新代码崩了，旧版本依然能撑住。
- **对比：** 让你在不影响老同事工作的情况下，测试你的新 Chatbot 逻辑。

## 3. 部署时，你必须配置的“三要素”

由于你用的是 **Azure OpenAI**，你的 `chainlit` 程序需要通过环境变量拿到“大脑”的准入证。在部署 Container Apps 时，一定要检查这三个参数：

| **变量名 (常见写法)** | **来源 (Azure OpenAI Resource)** | **作用** |
| --- | --- | --- |
| `AZURE_OPENAI_API_KEY` | Keys and Endpoint 页面 | 你的身份密码 |
| `AZURE_OPENAI_ENDPOINT` | Keys and Endpoint 页面 | 告诉程序去哪找模型 (URL) |
| `AZURE_OPENAI_DEPLOYMENT_NAME` | Model deployments 页面 | 告诉程序用哪个模型 (比如 `gpt-4o`) |

## 4. 给你的操作建议（避坑指南）

### B. 检查“Ingress”设置

在部署 Container Apps 时，确保 **Ingress (入口)** 已启用，并且端口设置为 `8000`（或者你在 Dockerfile 里指定的端口），否则你无法通过浏览器看到 Chatbot 界面。

### C. 既然要“并行”

在 Azure 门户或 CLI 部署时，寻找 **"Revision Mode"** 选项：

- 将其设置为 **"Multiple"**（多版本模式）。
- 这样你每点一次部署，它都会生成一个新版本，而不会直接覆盖掉旧的。

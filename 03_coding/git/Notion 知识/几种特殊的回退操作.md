# 几种特殊的回退操作

## 🧩 情况 1：`commit`之后发现有问题，想要**修改或补充**内容

### ✅ 目标：

把新修改加入**上一条提交**中，保持 commit 整洁

### ✅ 推荐操作：

```bash

# 修改代码后
git add .                          # 或者 git add <file>
git commit --amend

```

或者直接修改 message：

```bash
git commit --amend -m "new message"
```

### ⚠️ 注意：

- 如果还**没 push**，使用 `-amend` 非常安全。
- **目的：保持一个干净的提交记录**

---

## 🌐 情况 2：`push`之后，发现还有相似修改想补充到上次 push 的修改中

### ✅ 目标：

把新改动**合并进上一条已经 push 的提交**中（并不产生新的 commit）

### ✅ 推荐操作：

```bash

git add .                      # 暂存新改动
git commit --amend             # 合并成一条提交
git push --force               # 强推覆盖远端提交

```

### ⚠️ 风险：

- 强推（`-force`）会修改远端历史，**多人协作时请务必确认安全**
- 如果不想影响别人，使用 `git push --force-with-lease` 更安全些

---

## 🧯 情况 3：已经 `push` 了，发现 commit 有 问题，想要撤销并修改

### ✅ 目标：

撤销远端的 bug commit，并替换成修正后的版本

### ✅ 推荐操作：

### 方法 1：使用 `revert`（**推荐，安全**）

```bash

git revert <commit-hash>
# 然后修复问题
git add .
git commit -m "fix bug"
git push

```

> 会生成一条“撤销上次提交”的新提交，不改历史
> 

## `git revert` 时不知道要撤销的那条 commit hash 怎么办？

### 用引用符号直接指向最近的提交

| 引用 | 代表 | 例子 | 说明 |
| --- | --- | --- | --- |
| `HEAD` | 当前提交 | `git revert HEAD` | 撤销最新一次提交 |
| `HEAD~1` / `HEAD^` | 倒数第 1 条之前 | `git revert HEAD~1` | 撤销“倒数第二”条 |
| `HEAD~2` | 倒数第 2 条之前 | `git revert HEAD~2` | 依此类推 |

> 如果只是要撤销刚刚推送那一次，通常 git revert HEAD 就够了。
> 
> 
> 需要回滚更早的，可数 `~N`。
> 

### 方法 2：修改本地历史后强推（**有风险**）

```bash

git rebase -i HEAD~1            # 或更多，找出那次有 bug 的提交
# 修改或删掉
git push --force

```

### ⚠️ 建议：

- 如果团队合作，**使用 `revert` 更安全**
- 如果是自己分支或测试分支，`-force` 也可以接受

---

## 🧪 情况 4：`push` 时不确定对不对，**怕影响正式代码**

### ✅ 目标：

在不污染正式代码的情况下先测试新提交

### ✅ 推荐做法：

### 方法 1：**推送到临时分支测试**

```bash

git checkout -b temp/test-branch
git push origin temp/test-branch

```

→ 可以在 CI 或测试环境验证后，再合并

### 方法 2：使用 `draft` 或 `WIP` 标题避免误 merge（配合 PR 流程）

### 方法 3：使用 `pre-push` 脚本做检测（自动 lint/test）

---

## 🔖 总结速查表

| 情况 | 推荐操作 | 是否需要 `--force` |
| --- | --- | --- |
| commit 后想补改内容 | `git commit --amend` | 否 |
| push 后想补改内容 | `git commit --amend` + `push --force` | ✅ |
| push 后发现错误 | `git revert` 或 `rebase -i` + `push --force` | 看方法 |
| 不确定是否正确 | 新建分支推送 | 否 |

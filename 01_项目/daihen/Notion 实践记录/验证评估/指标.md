# OCR模型评估指标详解

## 1. 编辑距离 (Edit Distance) 详解

### 1.1 什么是编辑距离?

**编辑距离(Edit Distance)**,也叫 **Levenshtein距离**,是指将一个字符串转换成另一个字符串所需的**最少编辑操作次数**。

允许的编辑操作包括:
1. **插入(Insert)**: 插入一个字符
2. **删除(Delete)**: 删除一个字符  
3. **替换(Substitute)**: 替换一个字符

### 1.2 编辑距离示例

**例子1: 识别错误**
```
预测结果: "A123456"
真实标签: "A123457"
编辑距离: 1 (需要替换最后一个字符 6→7)
```

**例子2: 缺字**
```
预测结果: "A12345"
真实标签: "A123456"
编辑距离: 1 (需要插入字符 "6")
```

**例子3: 多字**
```
预测结果: "A1234567"
真实标签: "A123456"
编辑距离: 1 (需要删除字符 "7")
```

**例子4: 完全错误**
```
预测结果: "ABC123"
真实标签: "DEF456"
编辑距离: 6 (需要替换所有6个字符)
```

### 1.3 归一化编辑距离 (Normalized Edit Distance)

**定义**:
```
归一化编辑距离 = 编辑距离 / max(预测长度, 标签长度)
```

**为什么要归一化?**
- 不同长度的字符串,编辑距离的绝对值难以对比
- 归一化后变成0-1之间的值,便于评估

**PaddleOCR中的实现**:
```python
# 源码: ppocr/metrics/rec_metric.py
norm_edit_dis += Levenshtein.normalized_distance(pred, target)
# 最后返回: 1 - norm_edit_dis (转换为相似度)
```

**示例计算**:
```
预测: "A12345"  (长度6)
标签: "A123456" (长度7)
编辑距离: 1
最大长度: 7
归一化编辑距离: 1/7 = 0.143
返回值(相似度): 1 - 0.143 = 0.857 (85.7%相似)
```

---

### 1.4 编辑距离 vs CER

#### 编辑距离 (Edit Distance)
- **计算单位**: 字符串整体
- **关注**: 两个完整字符串之间的差异
- **值域**: 0到max(len1, len2)
- **归一化后**: 0-1之间,越接近1越好

#### CER (Character Error Rate, 字符错误率)
- **计算单位**: 字符级别
- **定义**: `CER = (插入+删除+替换) / 标签字符数`
- **值域**: 0到正无穷(理论上)
- **应用**: 语音识别(ASR)常用

**关系**:
```
CER ≈ 编辑距离 / 标签长度
归一化编辑距离 ≈ 编辑距离 / max(预测长度, 标签长度)
```

**在PaddleOCR中**:
- 使用的是 **归一化编辑距离**,不是CER
- 但两者本质类似,都是衡量字符级别的差异

## 2. 训练曲线中的各项指标详解

### 2.1 文字检测(Detection)指标

#### 2.1.1 Loss (损失函数)
**含义**: 模型预测结果与真实标签的差距
- **值越小越好**
- 理想情况下应该持续下降并趋于稳定
- 如果训练loss下降但验证指标不上升,说明过拟合

**在检测任务中的组成**:
```python
# DBLoss (PaddleOCR检测损失)
Loss = balance_loss * (
    α * shrink_map_loss +    # 文本区域收缩图损失
    β * threshold_map_loss   # 阈值图损失
)
```

#### 2.1.2 Precision (精确率/查准率)
**定义**:
```
Precision = 正确检测的文本框数 / 模型检测出的文本框总数
```

**含义**: 模型检测出的文本框中,有多少是真正的文本?
- **值域**: 0-1,越接近1越好
- 关注"**查准**"能力

**示例**:
```
模型检测出100个文本框
其中95个是真正的文本,5个是误检(背景)
Precision = 95/100 = 0.95 (95%)
```

#### 2.1.3 Recall (召回率/查全率)
**定义**:
```
Recall = 正确检测的文本框数 / 图像中实际文本框总数
```

**含义**: 图像中所有的文本,模型找到了多少?
- **值域**: 0-1,越接近1越好
- 关注"**查全**"能力

**示例**:
```
图像中实际有100个文本框
模型检测出95个
Recall = 95/100 = 0.95 (95%)
```

#### 2.1.4 Hmean (F1-Score / 调和平均数)
**定义**:
```
Hmean = 2 * Precision * Recall / (Precision + Recall)
```

**含义**: Precision和Recall的综合评价
- **值域**: 0-1,越接近1越好
- 是检测任务的**核心指标**
- 平衡了"查准"和"查全"

**为什么用调和平均而不是算术平均?**
```
假设: Precision=1.0, Recall=0.5
算术平均: (1.0+0.5)/2 = 0.75  ← 会被高分拉高
调和平均: 2*1.0*0.5/(1.0+0.5) = 0.67 ← 会被低分拉低

→ 调和平均对低分更敏感,更能反映模型的真实性能
```

**您的检测模型结果**:
```
Precision: 1.0   ← 检测出的都是真文本(无误检)
Recall: 1.0      ← 所有文本都被检测到(无漏检)
Hmean: 1.0       ← 完美性能!
```

Loss = CTCLoss + NRTRLoss

#### 2.2.2 Accuracy (准确率)
**定义**:
```
Accuracy = 完全正确识别的样本数 / 总样本数
```

**注意**: 这是**字符串级别的完全匹配**!
- 一个字符错误 → 整个样本算错
- 非常严格的指标

**示例**:
```
预测: "A123456"
标签: "A123457"
→ 准确率: 0 (不算正确,因为最后一个字符不同)

预测: "A123457"
标签: "A123457"
→ 准确率: 1 (完全匹配)
```

**您的识别模型结果**:
```
最高: 93.13% (Epoch 6)  ← 93.13%的样本完全正确
最终: 54.51% (Epoch 200) ← 过拟合后严重下降
```

#### 2.2.3 Normalized Edit Distance (归一化编辑距离)
**前面已详细解释,这里强调其在识别任务中的意义**:

**为什么需要这个指标?**
- Accuracy太严格(一个字符错就全错)
- 编辑距离能体现"错得有多离谱"

**实际应用意义**:
```
场景: 制造番号识别 "A123456"

情况1: 预测 "A123457"
- Accuracy: 0% (完全不算)
- Edit Distance: 0.857 (85.7%相似) ← 更合理

情况2: 预测 "XXXXXXX"
- Accuracy: 0% (同样不算)
- Edit Distance: 0.0 (完全不同) ← 能区分严重程度
```

**您的识别模型结果**:
```

## 3. 指标之间的关系

### 3.1 检测任务中的平衡

```
高Precision + 低Recall → 保守策略(宁可漏检,不要误检)
低Precision + 高Recall → 激进策略(宁可误检,不要漏检)
高Hmean → Precision和Recall都高(最佳状态)
```

**您的检测模型**: 两者都达到1.0,完美平衡!

### 3.2 识别任务中的互补

```
Accuracy        ← 严格的完全匹配指标
Edit Distance   ← 宽容的相似度指标

两者结合才能全面评估模型:
- Accuracy高 + EditDist高 → 优秀模型
- Accuracy低 + EditDist高 → 能识别大部分,但有小错误
- Accuracy低 + EditDist低 → 模型失效
```

**您的识别模型(Epoch 6)**:
```
Accuracy: 93.13%        ← 93%完全正确
Edit Distance: 0.9772   ← 剩余7%的样本平均相似度97%
→ 综合评价: 优秀!
```

## 6. 常见问题解答

### Q1: 为什么我的Accuracy只有93%,Edit Distance却有97%?

**A**: 因为Accuracy是完全匹配,非常严格!

```
假设100个样本:
- 93个: 完全正确 → Accuracy计数
- 7个: 有1-2个字符错误 → 不计入Accuracy,但Edit Distance很高(0.97+)

最终:
Accuracy = 93/100 = 93%
平均Edit Distance = (93*1.0 + 7*0.97) / 100 = 97.72%
```

### Q2: Hmean是什么意思?为什么它是主指标?

**A**: Hmean = 调和平均数 = F1-Score

```
假设两个模型:
模型A: Precision=1.0, Recall=0.6  → Hmean=0.75
模型B: Precision=0.8, Recall=0.8  → Hmean=0.80

虽然A的Precision更高,但B更平衡,实际应用中B更好!
```

### Q3: Loss下降为什么性能反而下降?

**A**: 这就是过拟合!

```
Loss下降 → 模型在训练集上表现越来越好
但如果模型记住了训练数据的噪声,在验证集上反而变差
```

## 7. 指标选择建议

### 7.1 检测任务优先级
1. **Hmean** (核心指标) - 综合评价
2. **Precision** - 误检是否可接受
3. **Recall** - 漏检是否可接受
4. **Loss** - 辅助判断训练状态

### 7.2 识别任务优先级
1. **Accuracy** (核心指标) - 完全正确率
2. **Edit Distance** - 辅助评估错误严重程度
3. **Loss** - 辅助判断训练状态

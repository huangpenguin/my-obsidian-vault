# インターンシップ・プロジェクト提案書 (35日間)

## 1. 核心推奨プロジェクト：Sphero-Arm 高速インターセプトシステム

このプロジェクトでは、Sphero ボールロボットを高周波の動的入力ソースとして利用し、視覚情報がない、あるいは限定的な環境下で、**強化学習（RL）による予測**を用いて高速移動する物体のインターセプト（遮断）を機械学習させます。

### 1.1 プロジェクトビジョンと MVP

- **MVP (最小実行可能製品):** 手動で操作される Sphero ボールが机の上をランダムに転がる際、機械臂が 0.5 秒以内に軌道を計算し、適切な位置に移動してボールを阻止します。視覚センサーを使わず（内部センサーデータのみ）、指定区域内の不規則な動きに対し、インターセプト率 80% 以上を目指します。
- **核心的挑戦:** 物理的な遅延を克服し、「データ取得」から「事前インターセプト」への予測能力を実現すること。

### 1.2 インターンシップ・マイルストーン (35日間 / 280時間)

| **フェーズ** | **期間** | **目標** | **主な成果物** |
| :--- | :--- | :--- | :--- |
| **P1: インフラ構築** | 第1週 | Unityでラボ環境を1:1で再現。[Sphero](https://drive.google.com/file/d/1qEnxNFYqOHyAGAdEwf_u1fE5BN8mrqeM/view) と Unity のリアルタイム通信を確立。`mlagents_envs` Python ライブラリを使用して Python から仮想アームを制御。 | 仮想と現実の同期デモ |
| **P2: 強化学習訓練** | 第2-3週 | Unity ML-Agents で RL モデルを訓練。報酬関数を設計し、異なる速度・軌道のボールをインターセプトする方法を学習（Stable Baselines3 等を使用）。 | 学習済み PPO モデル (.onnx) |
| **P3: 座標キャリブレーション** | 第4週 | 物理空間のキャリブレーションを行い、仮想座標系と ROS 機械臂座標系を同期。 | 誤差 2cm 以内の校正ドキュメント |
| **P4: 実機デプロイ** | 第5週 | モデルを実機に適用し、動的インターセプトテストおよびデモ動画の撮影。 | 実機デモ動画 ＆ ソースコード |

### 1.3 役割分担

- **インターン (Shashank Arja):**
  - Unity 環境の構築（物理シミュレーション）。
  - C# によるロジック実装（Sphero IMU データと仮想オブジェクトのマッピング）。
  - モデル訓練（報酬関数の調整、シミュレーション環境での学習）。
- **メンター/チーム:**
  - アルゴリズム指導（PPO, SAC 等の選定支援）。
  - ハードウェアインターフェース提供（ROS 制御の封装 API）。
  - 物理的な座標補正のサポート。

### 1.4 AI ロジックアーキテクチャ (強化学習プロンプト思考)

- **状態空間 (State):** "現在のボールの座標 $P(x,y,z)$、速度 $V(x,y,z)$、および機械臂の各関節角度 $\theta$。"
- **行動空間 (Action):** "6つの関節の角速度 $\Delta\theta$ を制御し、エンドエフェクタをボールの未来の軌道上に移動させる。"
- **報酬関数 (Reward):**
  - **インターセプト報酬:** ボールを阻止した際に大きな正のフィードバック（+100）。
  - **距離報酬:** エンドエフェクタがボールに 5cm 以内に近づけば +10。
  - **予測奨励:** 0.2 秒先にボールの進路に到達していれば追加加点。
  - **物理ペナルティ:** 過度な振動（-0.1）、机への衝突（-100 ＆ リセット）、急激な加速度（-10）。

## 2. AIフロー状態「ディレクター」システム (AI Flow-State Director)

プレイヤーのパフォーマンスをリアルタイムで監視し、ゲーム環境を動的に調整することで、プレイヤーを常に「フロー状態」（退屈せず、絶望もしない状態）に保つ AI を開発します。

### 2.1 プロジェクトビジョンと MVP

- **プロジェクト核心:** 強化学習に基づいた動的難易度調整（DDA）フレームワークの構築。
- **MVP:** 基礎的なサバイバル/アクションゲーム。AI ディレクターがプレイヤーの残 HP や撃破速度に基づき、敵の数や補給品の生成をリアルタイムで決定します。

### 2.2 マイルストーン (35日間)
- **W1:** Unity で基礎プロトタイプ作成。AI が調整可能なパラメータ（敵の能力値等）を確定。
- **W2:** プレイヤーデータ（HP、命中率等）をリアルタイム収集する C# スクリプトの実装。
- **W3:** 仮想環境での大量シミュレーションによる「ディレクター AI」の訓練。
- **W4:** 実際のユーザーテストによる、ゲーム体験の向上（面白さ）の検証。
- **W5:** システムのモジュール化とデモ動画作成。

## 3. 好奇心駆動型自動テストBot (Curiosity-based QA Bot)

インターンの [QA テストの知識](https://drive.google.com/file/d/1qEnxNFYqOHyAGAdEwf_u1fE5BN8mrqeM/view) を活かし、強化学習の「内的好奇心」メカニズムを利用して、ゲームの境界を自律的に探索しバグを発見するエージェントを開発します。

### 3.1 プロジェクトビジョンと MVP

- **プロジェクト核心:** 従来の手動テストの低効率とカバー率の低さを解決する。
- **MVP:** 複雑な 3D マップにおいて、人間が介入することなく、Bot が自律的にロジックの脆弱性（壁抜け、スタック、イベント未発生）を発見し、座標と動画を自動記録します。

### 3.2 マイルストーン (35日間)
- **W1:** バグ（意図的な不具合）を含む Unity テスト環境の構築。
- **W2:** ML-Agents の RND アルゴリズムを統合し、Bot に探索意欲を付与。
- **W3:** 異常状態（速度異常、落下等）を自動検知・記録するロジックの実装。
- **W4:** 探索効率の最適化とヒートマップの生成。
- **W5:** 自動テストレポート生成ツールの完成。

## 技術選定に関する補足

### なぜ NVIDIA Isaac Gym ではなく Unity なのか
1. **実現可能性の検証:** Unity を使用することで「Sphero データの予測インターセプト」というロジックを迅速に検証できます。
2. **データハブとしての価値:** Unity は優れた可視化ツールであり、後に NVIDIA で訓練されたアルゴリズムのデモ用フロントエンドとしても活用可能です。

### ML-Agents Python API の採用
インターンに **OpenAI Gym** のようなスタイルで Unity を操作させます（ベースラインとして内蔵アルゴリズムを使用し、後に PPO を独自実装して改良します）。
- **環境構築のリスク回避:** Isaac Gym はドライバやOSの制約が厳しいですが、Unity は即座に開発可能です。
- **アルゴリズムの深化:** 状態処理や報酬計算を Python 側で自ら実装させることで、単純なゲーム制作以上の「AI エンジニアリング」としての深さを担保します。
- **キャリアへの貢献:** 「Python API を用いて Unity 上でロボット制御を実現した」という実績は、非常に高い市場価値を持ちます。

#### ステップ 1：古いドライバのクリーンアップによる依存関係エラーの解消

- **コマンド：**
    
    Bash
    
    ```
    sudo apt-get remove --purge '^nvidia-.*'
    sudo apt-get remove --purge '^libnvidia-.*'
    sudo apt-get autoremove
    ```
    
- **理由：** 新しいドライバのインストール時に依存関係の競合（held broken packages）が発生したため。システムの破損（いわゆる「OSが落ちる」状態）を防ぎ、高バージョンのドライバをクリーンに導入するには、古いドライバ一式と関連ファイルを完全にアンインストールする必要がありました。
    

#### ステップ 2：データセンター向け 570-Server ドライバのインストールと再起動

- **コマンド：**
    
    Bash
    
    ```
    sudo apt install nvidia-driver-570-server
    sudo reboot
    ```
    
- **理由：** 4枚の V100 というエンタープライズ向けの計算リソースに対しては、最新の通常版よりも、长期サポート（Production Branch）である `-server` 安定版を選択する方が堅牢です。これにより、マルチGPUによる高負荷な学習時の「GPU認識エラー（显卡掉线）」を防ぎます。また、新しいカーネルモジュールを読み込ませるためにソフトリブート（`reboot`）が不可欠でした。
    

#### ステップ 3：NVIDIA Container Toolkit（架け橋）の設定

- **コマンド：**
    
    Bash
    
    ```
    # 公式リポジトリ設定後、ツールをインストールし、以下を実行
    sudo nvidia-ctk runtime configure --runtime=docker
    sudo systemctl restart docker
    ```
    
- **理由：** コンテナ運用の原則は「ホスト側にはドライバのみ、CUDA環境はコンテナ内に構築する」です。しかし、デフォルトの Docker は GPU を認識できないため、4枚の V100 をコンテナへ透過的に割り当てる（パススルーする）ための架け橋として Container Toolkit の導入が必要です。
    

#### ステップ 4：環境検証と Docker バージョンの確認

- **コマンド：**
    
    Bash
    
    ```
    docker --version
    sudo docker run --rm --gpus all nvidia/cuda:11.8.0-base-ubuntu20.04 nvidia-smi
    ```
    
- **理由：** Docker のバージョンが `--gpus` オプションに対応している（19.03以上である）ことを確認するためです（他ユーザーのタスク中断を防ぐため、Docker 本体のアップデートは敢えて見送りました）。最終的に、テスト用コンテナ内で `nvidia-smi` の出力に成功したため、GPU パススルー環境の構築完了を確認できました。今後は安心して Dockerfile の作成に移行できます。 """

### 1. プロジェクトの位置づけ

- AI コーディング規約とMLOps（Docker / GitLab CI / GPU 学習）を一体にした再利用可能なテンプレートを整備しました。
- 新規・既存プロジェクトでは `init-ai` 一コマンドで、Cursor ルール・品質チェック・CI/CD・Docker 設定をまとめて注入できます。

> 本リポジトリは、AI 開発ルールと MLOps パイプラインを標準化した社内テンプレートです。メンバーはプロジェクトを pull し `init-ai` するだけで CI/CD と Docker ベースの開発環境の骨格が揃い、Windows でも Docker 対応 PC なら個別セットアップを大幅に削減できます。GPU 学習は gpu-server に集約し、GitLab からワンクリックで実行できるようにしました。

### 3. 価値（Windows 環境を含む）

（Windows）・非 GPU メンバー向け

- 本番 GPU 学習は gpu-server 上の GitLab Runner が担当。Windows PC 上で GPU や Docker を深く触る必要はありません。
- コード品質チェック（Ruff / Pyright）は GitLab / GitHub の CI が自動実行。ローカルに Python 環境を揃えなくても、push すれば結果を Web で確認できます。
- 開発時は Cursor + Remote SSH / Dev Containers を想定。Windows でも Docker Desktop + ドライバが要件を満たせば、リポジトリを pull するだけで、チーム共通のコンテナ環境に入れます（手動で uv / Ruff / Pyright を都度設定する必要を減らせます）。
- 新プロジェクト参加時は `init-ai` 一発で、AI ルールと CI/CD テンプレが揃い、属人化した「環境構築メモ」依存を軽減できます。

GPU サーバー担当（gpu01 等）向け

- push 後、GitLab 上で Play ボタン（または commit `[run train]`）で学習ジョブを起動。各サーバーへ SSH して pull し直す運用を減らせます。
- Runner は `shell` executor + tag `gpu-server` が前提（設定済みであれば、学習用 Docker はプロジェクトの `Dockerfile` に従います）。

チーム全体

- テンプレート 1 本を更新 → `git pull` → 各プロジェクトで `init-ai --update` により、ルールと CI 設定の横展開が可能です。
- 詳細手順は `docs/MLOPS-CHECKLIST.zh-CN.md` に集約（README は概要のみ）。

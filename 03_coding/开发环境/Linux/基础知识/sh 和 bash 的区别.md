# sh 和 bash 的区别

首先，我们要明确它们的关系：

- **`sh` (Bourne Shell)**：这是最早、最基础的 Unix shell。它定义了 shell 脚本的基本语法和功能。
- **`bash` (Bourne-Again SHell)**：它是 GNU 项目开发的，旨在成为 `sh` 的免费替代品。`bash` 完全兼容 `sh` 的语法，并且在此基础上增加了大量功能和改进。在大多数 Linux 发行版（包括 Ubuntu）中，`/bin/sh` 通常是一个指向 `bash` 或其他 `sh` 兼容 shell（如 `dash`）的**符号链接**。在 Ubuntu 中，`/bin/sh` 默认指向 `dash`。

**`dash` (Debian Almquist Shell)**：这是一个更小、更快的 `sh` 兼容 shell，它被设计成轻量级和高效，因此在 Ubuntu 中作为 `/bin/sh` 的默认实现，主要用于系统启动脚本和脚本执行，因为它启动快，资源占用少。

**关键区别：**

| 特性 | `sh` (或 `dash`) | `bash` |
| --- | --- | --- |
| **兼容性** | 严格遵循 POSIX shell 标准。 | **完全兼容 POSIX `sh` 标准**，但在此基础上增加了大量扩展。 |
| **功能** | 功能集较小，仅限于基本脚本功能。 | **功能强大得多**，包括：&lt;br> - **命令行编辑：** 更友好的光标移动、删除、插入（使用方向键、Home/End、Ctrl+A/E/K/U等）。&lt;br> - **命令历史：** 完整的命令历史记录（使用上下箭头），可搜索历史（Ctrl+R）。&lt;br> - **命令补全：** 按 Tab 键自动补全命令、文件名、目录名（由 `bash-completion` 提供）。&lt;br> - **进程控制：** `fg`, `bg`, `jobs` 命令。&lt;br> - **别名 (Aliases)：** 可以定义命令的快捷方式。&lt;br> - **Shell 选项 (`shopt`)：** 更多可配置的 shell 行为。&lt;br> - **更丰富的编程特性：** 关联数组、更高级的条件判断 `[[...]]`、算术运算 `((...))` 等。 |
| **性能/资源** | 更小，启动更快，资源占用更少。 | 功能更多，因此相对更大，启动略慢，资源占用略多（但对于现代硬件来说，这点差异几乎可以忽略）。 |
| **常见用途** | 系统启动脚本、安装脚本、需要高性能且简单的脚本。 | 用户交互式登录 shell（你日常使用的终端）、复杂的自动化脚本、开发环境。 |

### 为什么会出现你的问题？

你的 `.bashrc` 文件和 Conda 的初始化脚本是为 `bash` 设计的。它们包含了 `bash` 特有的语法（如 `shopt` 命令、函数定义、更复杂的变量展开等）。当你在一个 `sh` 环境中执行这些脚本时，`sh` 无法理解这些 `bash` 特有的语法，因此就会报错。

### 一般用哪个比较好？

**对于用户交互式操作和服务器管理，以及编写大多数应用程序脚本，毫无疑问地选择 `bash` 更优。**

**理由如下：**

1. **用户友好性：** `bash` 提供了命令历史、命令补全、命令行编辑等极大的便利性，这在日常操作和调试中能节省大量时间。
2. **功能强大：** 更多的内置命令和编程特性，使得 `bash` 能够编写更复杂、更健壮的脚本。
3. **兼容性：** 几乎所有在 `sh` 中能运行的脚本也能在 `bash` 中运行（反之则不然）。
4. **生态系统：** 绝大多数的 Linux 用户、教程、社区都是基于 `bash` 的，很多第三方工具（如 `bash-completion`）也依赖 `bash`。

**什么时候会用到 `sh` (或 `dash`)？**

- **系统启动脚本：** Ubuntu 为了追求启动速度和资源效率，将 `/bin/sh` 指向 `dash`，以便快速执行系统启动时那些简单的、不依赖 `bash` 特性的脚本。
- **资源极度受限的环境：** 在嵌入式设备或旧硬件上，为了节省每一字节内存和每一毫秒启动时间，可能会优先使用 `dash`。
- **确保脚本的移植性：** 如果你编写的脚本需要在各种不同的 Unix-like 系统上都能运行，并且只使用最基本的 shell 语法，那么在脚本开头指定 `#!/bin/sh` 是一个好习惯，并确保只使用 `sh` 兼容的语法。

### 如何配置你的新服务器 (确保使用 `bash`)

鉴于你是新创建的服务器，并且要进行开发和服务器管理，**你应该确保你的用户默认登录 Shell 是 `bash`。**

1. **检查当前用户的默认 Shell：**Bash
    
    `echo $SHELL`
    
    如果输出是 `/bin/sh`，那么就需要修改。
    
2. **修改你的用户默认登录 Shell 为 `/bin/bash`：**
这是最推荐的，一旦修改并重新登录，你所有的 SSH 会话都会自动进入 Bash 环境。Bash
    
    `chsh -s /bin/bash`
    
    - 执行后会提示你输入当前用户的密码。
    - **修改后，你需要注销当前 SSH 会话并重新登录，才能使更改生效。**
3. **重新登录后确认：**
再次 SSH 登录服务器，然后执行 `echo $SHELL`，这次应该显示 `/bin/bash` 了。
4. **加载 Conda 环境：**
如果 Conda 的 `(base)` 环境没有自动激活（提示符前没有 `(base)`），那么执行：Bash
    
    `source ~/.bashrc`
    
    这次应该能成功加载了，并且你就可以正常使用 `conda` 命令了。
    

通过将你的用户默认 Shell 设置为 `bash`，你将获得一个更强大、更用户友好的命令行环境，并解决与 Conda 初始化脚本的兼容性问题。

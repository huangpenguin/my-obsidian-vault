多 Agent 闭环在这个场景下如何运转？

面对这种极端的工业场景，编排式多 Agent 的优势将被发挥到极致：

```
[现场人员上传反光/模糊的日文电力铭板图]
                     │
                     ▼
       [OpenCV 自动进行 CLAHE 图像增强]
                     │
                     ▼
     [Generator Agent (调用 Azure/Gemini)]
     - 识别图像，提取出日文结构化 JSON 数据
                     │
                     ▼
      [Vision & Rule QA Agent (双重审计)]
      - 检查 1: 日文核心电力术语是否完整？
      - 检查 2: Pydantic 校验 (V * A == kW 是否成立？)
                     │
                     ├─── (审计失败: 物理公式不匹配/型号格式错)
                     │    - 提取失败原因: "第 3 位数字由于反光疑似把 8 看成了 0"
                     │
                     │    ▼
                     │ [Refiner Agent 介入]
                     │ - 重新打包图像增强变体 (如锐化图)
                     │ - 注入提示词: "请重点核对功率因数附近的数字..."
                     │ - 重新丢回 Generator 重试
                     │
                (审计成功)
                     │
                     ▼
    [正式写入 SQLite 状态机，判定 SUCCESS，数据入库]
```

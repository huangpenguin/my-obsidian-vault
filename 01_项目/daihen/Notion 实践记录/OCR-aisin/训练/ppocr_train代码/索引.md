# ppocr_train代码

```markdown
nohup python -u -m paddle.distributed.launch \
  --ips="192.168.3.18" \
  --gpus "0,1,2,3" \
  tools/train.py \
  -c ../tray_recog/configs/rec/rec_ppocr_v3_baseline.yml \
  > output/rec_ppocr_v3_baseline.yml.log 2>&1 &
```

### `nohup`

> 意思：即使终端关闭，仍继续运行程序。
> 
- 用于后台运行训练任务，防止 SSH 断开导致训练中断。
- 会将输出写入指定的日志文件。

---

### `python -u`

- `python`：调用 Python 解释器。
- `u`：**取消标准输出缓存**，保证日志**即时打印**（很重要，尤其是在 nohup 环境中查看日志）。

---

### `m paddle.distributed.launch`

> 启动 Paddle 的分布式训练模块。
> 
- `m` 表示运行一个 Python 模块；
- `paddle.distributed.launch` 是 PaddlePaddle 官方提供的**多卡/多机训练启动器**。

用于多 GPU、甚至多机器的训练调度。

[模块化原因](%E6%A8%A1%E5%9D%97%E5%8C%96%E5%8E%9F%E5%9B%A0.md)

---

### `-ips="192.168.3.18"`

> 指定主机 IP 地址。
> 
- 用于多机训练时，指定所有参与训练的机器的 IP 地址；
- 在单机训练中，它告诉 launch 哪台是主节点（通常就是当前机器）；
- 如果你只有一台机器，这里就是它自己的 IP。

---

### `-gpus "0,1,2,3"`

> 指定使用的 GPU 设备编号。
> 
- 表示使用 GPU 编号为 0、1、2、3 的共 4 块卡来进行并行训练；
- Paddle 会自动在这些卡上分配数据和计算任务；
- 若只使用一张卡，写 `"0"` 即可。

---

### `tools/train.py`

> 训练主程序脚本。
> 
- PaddleOCR 的标准训练入口文件；
- 内部会根据配置文件启动模型、加载数据、优化器等逻辑。

---

### `c ../tray_recog/configs/rec/rec_ppocr_v3_baseline.yml`

> -c 是 config 的简写，表示加载指定的 YAML 配置文件。
> 
- 这是你的模型训练配置文件路径；
- 文件中定义了模型结构、优化器、学习率、数据路径等关键训练参数；
- 比如使用的是 `PP-OCRv3` 的识别模型（`rec`），作为一个 baseline。

---

### `> output/rec_ppocr_v3_baseline.yml.log 2>&1`

> 重定向输出日志（标准输出和标准错误一起保存）
> 
- `>` 表示将标准输出（stdout）写入日志文件；
- `2>&1` 表示将标准错误（stderr）也重定向到标准输出；
- 所以这两者一起写，会把所有训练信息都写入：
    
    ```
    output/rec_ppocr_v3_baseline.yml.log
    
    ```
    

你可以通过 `tail -f output/rec_ppocr_v3_baseline.yml.log` 实时查看训练日志。

---

### `&`

> 表示将整个命令在后台运行。
> 
- 你可以在当前终端继续使用其他命令；
- 如果没有 `nohup` + `&`，关闭终端时训练进程会被杀死。

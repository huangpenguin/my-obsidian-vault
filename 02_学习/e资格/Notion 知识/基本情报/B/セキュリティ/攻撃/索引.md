# 攻撃

***SQL インジェクション攻撃***とは、SQL で操作する***データベース***を使用しているアプリケーションに対して、不正な SQL 文を注入(injection)して、 データベースを不正に操作する攻撃です。Web サイトの入力フォームなどから不正な SQL 文を送信して、データベースに不正な操作を行わせる攻撃。入力した文字列から SQL 文（データベースに対する処理の命令）を組み立てるプログラムに、 SQL で使われる特殊文字（引用符など、特別な意味を持たせた文字）を含めて、データベースに予期しない処理をさせる攻撃です。**特殊文字としての意味を失わせるエスケープ**処理をすれば、通常の文字として処理されるので、この攻撃を防ぐことができます。

***フィッシング攻撃***とは、正規のサイトに似せた偽サイトにアカウントとパスワードを入力するように仕向けて、盗んだ情報を悪用して正規サイトにログインしようとする攻撃です。

***DoS 攻撃：***標的となるサーバに大量のリクエストを要求することで、サーバ停止などの障害を発生させる。(针对DNS服务器)

***トロイの木馬：***マルウェア（不正プログラム）の一種で、コンピュータに潜んで動作し、データの漏えいや削除など不正な動作を行う。(常见于无偿软件的捆绑下载以及手机个人情报)

***ポートスキャン：***攻撃対象のサービスがどのポートで提供されているかを調べる。

***IP スプーフィング：***送信元 IP アドレスを***詐称***したパケットを送信する攻撃。

***クロスサイトスクリプティング：***Web サイトの入力フォームなどに、悪意のあるスクリプトを含むデータを送信して、悪意のある動作をさせる攻撃。 

***パスワードクラッキング：***パスワードを何らかの手段で割り出そうとする攻撃。

***ポートスキャン***：サーバで稼働しているサービスを探る目的で、多数のポート番号に対して通信を試みる攻撃。

***バッファオーバフロー***は、バッファ（データを受け入れるメモリ上の領域）として確保しているサイズを超えるデータを入力して、誤動作や意図しない動作を起こすことを狙う攻撃です。受け取ったデータをバッファに保存する際に、データサイズがバッファサイズを超えていないかチェックすることで、この攻撃を防ぐことができます。

プロキシサーバで中継するプロトコルのポート番号宛てのパケットだけ、 FW で通過を許可することで、***ポートスキャン攻撃***を防ぐことができます。

DNS サーバは、インターネット側の不***特定のホストからの名前解決の問い合わせを受け付ける***必要があるため、パケットの送信元 IP アドレスやポート番号を制限できず、不正アクセス攻撃を防ぐことができません。

***Web アプリケーションの脆弱性を悪用する攻撃***は、パケットのペイロード（データの中身）によって行われるため、パケットの送信元 IP アドレスやポート番号では判断できず、防ぐことができません。

***「ドライブバイダウンロード」（Drive-By Download）***は、ユーザーが意図せずにマルウェアをダウンロードしてしまうサイバー攻撃の一種です。これは、悪意のあるウェブサイトを訪れただけで、あるいは正規のサイトが攻撃者によって改ざんされた場合に発生することがあります。ユーザーが何もクリックしなくても、自動的にマルウェアがダウンロードされ、システムに感染することがあります。

### **ドライブバイダウンロードの仕組み**

1. **悪意のあるコードの埋め込み**
    - 攻撃者は、正規のウェブサイトや広告ネットワークに悪意のあるコードを埋め込みます。これには、クロスサイトスクリプティング（XSS）やSQLインジェクションなどの手法が使用されます。
2. **脆弱性の利用**
    - 悪意のあるコードは、ブラウザやそのプラグイン、オペレーティングシステムの脆弱性を利用して、マルウェアをダウンロードします。この脆弱性には、古いバージョンのソフトウェアや未パッチのシステムが特に狙われます。
3. **自動ダウンロードとインストール**
    - ユーザーが感染したページにアクセスすると、悪意のあるスクリプトが実行され、ユーザーの知らないうちにマルウェアが自動的にダウンロードされ、システムにインストールされます。

## 网络相关

ファイアウォールのパケットフィルタリングは、パケットの送信元または宛先の IP アドレスおよびポート番号を検査して、パケットの通過の許可・拒否を判断する仕組みです。（查包的时候只能确定ip和端口号）

### SSH

SSH は、サーバへの遠隔ログインのための通信プロトコルおよびソフトウェアであり、通信データの盗聴対策や、通信相手のなりすましを防ぐ仕組みを備えている。クライアントからサーバへのログインでは、サーバは利用者認証を行う。 SSH の利用者認証の方式には、デジタル署名を用いる公開鍵認証と、パスワードを用いるパスワード認証がある。 SSH では、ログイン時の利用者 ID とパスワードは暗号化されてネットワーク上を流れますので、盗聴はできません。

公開鍵認証では、クライアントの公開鍵を事前にサーバに登録しておき、この登録されている公開鍵に対応する秘密鍵をクライアントがもっていることをサーバが確認する。

パスワード認証では、クライアントが利用者 ID とパスワードを送信し、サーバは受け取ったパスワードが当該利用者のパスワードと一致していることを確認する。パスワード認証は、公開鍵認証に比べて安全性が低いと考えられている。

サーバで稼働しているサービスを調べる目的で、通信を待ち受けているポートを探ることを***ポートスキャン***と呼びます。トランスポート層のプロトコルに応じて、 TCP スキャンと UDP スキャンがあります。

セッション管理：クライアントとサーバ間の通信の通信を維持するための手順や活動

インシデント管理：システムで発生した障害などに対処する手順や活動

ログ管理：通信の履歴を適切に記録して保存する仕組みや手順

## パスワードについて

Q さんの氏名と生年月日を知る他者が、パスワードとして「姓＋生年月日」、「姓＋誕生日」、「名＋生年月日」、「名＋誕生日」などを試してログインしたと考えられます。このように、パスワードに使われそうな文字列を推測して入力する手法を、***類推攻撃***と呼びます。

また、同じアカウントとパスワードを複数のサービスで使い回す人がいることを想定して、他のサービスにログインしようとするのは、***パスワードリスト攻撃***です。

***総当たり攻撃***は、類推攻撃とは異なり、機械的に生成した多数のパスワードでログインしようとする攻撃です。

***ソーシャルエンジニアリング：***技術的手段を用いずに秘密情報などを得ようとする。具体的には、正規の担当者のふりをして電話をかけてパスワードを聞き出す、他人の PC を背後から覗き込んで情報を盗み見するなど。

ハッシュ関数に入力する文字列の桁数によらず、ハッシュ値の桁数は一定です。

## 病毒常见对策

【対策1】マルウェア定義ファイルの毎日の更新を強制的に実施する管理プログラムを導入する。

【対策2】 OS やアプリケーションソフトウェアのセキュリティパッチを強制的に適用する設定を選択する。

【対策3】不審な電子メールの添付ファイルは安易に開かず、電子メールの送信者に確認し、そのような電子メールが届いたことを 社内に周知する、というルールを 社内で徹底する。

USB メモリの利用時にマルウェアスキャンを強制的に実施する仕組みとする。

USB メモリは、マルウェア対策が実施済みで利用履歴が管理された専用の PC だけで利用可能とする。

## 邮件相关

***OP25B（Outbound Port 25 Blocking）***は、迷惑メールやウイルスメールの送信を抑制する目的で、自ネットワーク内から外部のメールサーバへのTCP/25番ポートへの直接の通信を遮断することです。

***PGP（Pretty Good Privacy）***は、当事者間で事前に公開鍵の交換を行って、暗号化した電子メールや電子署名を付加した電子メールを送受信する仕組みです。

***SPF（Sender Policy Framework）***は、電子メールの送信元ドメインが詐称されていないか検査する仕組みです。当該ドメインの DNS サーバに、正規の電子メールの送信メールサーバの IP アドレスを登録しておきます。電子メールの受信側では、送信元ドメインと送信メールサーバの整合性をチェックすることで、詐称されていれば検知できます。

以上より、「送信元を詐称した電子メールへの対応を検討し、【SPF】を導入することとした。【SPF】の導入によって、送信元を詐称した電子メールの【検知が可能】になる。」となります。

### HTTP

GET 、POST 、PUT はいずれも、 HTTP でクライアント（ Web ブラウザ ）から Web サーバへ送る HTTP リクエストです。

GET は、 URL の末尾に「?変数=値」の形式でパラメータを付加する方法です。電子メールや Web サイトで、 “ HTTPS://example.com/index.html?a=123&b=456” のようにリンクを張るときによく用いられます。送信する値が見えるため、パスワードや秘密情報の送信に用いることは不適切です。また、 URL が長くなるので、大量のデータ送信には向いていません。

これに対して POST は、 Web のフォームからのデータ送信に用いられることが多く、入力データが URL に現れないため、秘密情報や大量のデータの送信にも使うことができます。

PUT もデータ送信を行いますが、同じデータを複数回送信すると、 Web サーバ側で更新（上書き）されます。 POST では複数回送信すれば、その回数分のデータが追加されます。

クロスサイトリクエストフォージェリは、外部サイトを経由した悪意のあるリクエストを受け入れて予期しない処理をさせられてしまうことです。これを防ぐには、処理を実行するページに 、秘密情報が URL に現れない【POST】 メソッドでアクセスし、その「hiddenパラメータ」に秘密情報が挿入されるよう、前のページを自動生成して、実行ページではその値が正しい場合のみ処理を実行することが必要です。【GET】メソッドでアクセスすると、秘密情報を URL に付加して送信することになるので、利用を避けるべきです。

## 核心推荐项目：Sphero-Arm 敏捷拦截系统

该项目利用 Sphero 球形机器人作为高频动态输入源，训练机械臂在无视觉或弱视觉环境下，依靠**强化学习预判**实现对高速不规则运动物体的拦截。

### 1. 项目愿景与 MVP

- **MVP (最小可行性产品)：** 人手控制 Sphero 球在桌面上随意滚动，机械臂能够根据 Sphero 实时传回的坐标数据，在 0.5 秒内计算出拦截路径并移动到位，成功阻挡小球。 在无视觉（依靠传感器数据）的情况下，人手持 Sphero 球在指定区域内快速乱动，机械臂能实时预测球路，并提前移动到拦截点，实现“拦截率 > 80%”。
    
- **核心挑战：** 解决物理延迟，实现从“看到数据”到“提前拦截”的预测能力。

### 4. AI 逻辑架构 (强化学习 Prompt 思想)

在 RL 中，“Prompt” 表现为状态、动作和奖励函数的定义。我们可以将其理解为给 AI 下达的“指令：

- **状态空间 (State - AI看到什么):**
    
    > "你现在能看到小球的当前坐标 $P(x,y,z)$、当前速度 $V(x,y,z)$ 以及机械臂每个关节的角度 $\theta$。"
    
- **动作空间 (Action - AI能做什么):**
    
    > "你可以控制机械臂 6 个关节的角速度 $\Delta\theta$，目标是让机械臂末端移动到小球未来的轨迹线上。"
    
- **奖励函数 (Reward - AI的目标/Prompt 核心):**
    
    - **正向激励：** "如果末端执行器与球的距离 $d < 5cm$，获得 +10 分。"
        
    - **负向惩罚：** "如果动作过于剧烈导致机械臂震动，-0.1 分；如果撞击桌面，-100 分并重置。"
        
    - **效率激励：** "每消耗 1 毫秒时间，-0.01 分（引导 AI 寻找最短路径）。"
    -
	**拦截奖励：** "当末端坐标与球体坐标重合时，给予巨大的正反馈（+100）。"
    
- **预判鼓励：** "离球越近，得分越高。如果能提前 0.2 秒到达球路前方，额外加分。"
    
- **物理惩罚：** "禁止动作过快导致关节受力过大（-10）；绝对禁止碰撞基座或地面（-500 并重置）。"

# 智能心流“导演”系统 (AI Flow-State Director)

该项目旨在开发一个能“读懂玩家”的上帝视角 AI，通过实时监控玩家表现，动态调整游戏环境，确保玩家始终处于“心流”状态（既不因太难而沮丧，也不因太易而无聊）。

### 1. 项目愿景与 MVP

- **项目核心：** 建立一个基于强化学习的动态难度调节（DDA）框架。
    
- **MVP：** 一个基础的生存/动作游戏关卡。AI 导演根据玩家的剩余血量、击杀速度和移动轨迹，实时决定下一波敌人的数量、位置以及补给品的生成，使玩家的生存时间维持在预设的“挑战区间”内。
    

### 2. 实习里程碑 (35天)

|**阶段**|**任务目标**|**核心产出**|
|---|---|---|
|**W1: 游戏原型**|在 Unity 中搭建一个基础动作场景，确定可被 AI 调控的参数（如敌人 SP、补给概率）。|可运行的基础游戏 Demo|
|**W2: 状态采集**|编写 C# 脚本实时采集玩家数据（HP、准确率、压力值模型）。|玩家行为遥测系统|
|**W3: RL 训练**|在虚拟环境下通过大量模拟玩家，训练“导演 AI”学习如何通过调参来控制游戏节奏。|训练好的导演决策模型|
|**W4: 闭环验证**|邀请真实用户（或同事）试玩，验证 AI 是否能有效提升游戏趣味性。|难度曲线对比图表|
|**W5: 系统封装**|将导演系统模块化，使其能轻易接入其他 Unity 游戏项目。|导演系统插件包 & 演示视频|

### 3. 任务职责分担

- **实习生 ([Shashank Arja](https://drive.google.com/file/d/1qEnxNFYqOHyAGAdEwf_u1fE5BN8mrqeM/view)):**
    
    - 利用 [Valve Mod 经验](https://drive.google.com/file/d/1qEnxNFYqOHyAGAdEwf_u1fE5BN8mrqeM/view) 设计平衡逻辑。
        
    - 负责 Unity 内的 UI 与参数控制系统实现。
        
    - 编写模型训练脚本。
        
- **导师:**
    
    - 协助定义“心流”的数学评价指标。
        
    - 指导如何使用 Python 处理采集到的行为大数据。
        

### 4. AI 逻辑架构 (Logic Prompts)

- **Observation (AI 看到什么):** "玩家过去 30 秒的掉血速度、弹药消耗率、在某个区域的停留时间。"
    
- **Action (AI 调整什么):** "增加/减少 20% 敌人攻击力；在玩家视野盲区生成一个医疗包；改变背景音乐节奏。"
    
- **Reward (AI 的目标):** "如果玩家心率（模拟值）在 120 左右且持续玩下去，+10；如果玩家在 2 分钟内死亡或挂机，-50。"

# 好奇心驱动的自动化测试 Bot (Curiosity-based QA Bot)

该项目结合了 Shashank 的 [Software QA Testing 课程背景](https://drive.google.com/file/d/1qEnxNFYqOHyAGAdEwf_u1fE5BN8mrqeM/view)，利用强化学习中的“好奇心机制”（Intrinsic Curiosity）开发一个能自主探索游戏边界、寻找 Bug 的智能体。

### 1. 项目愿景与 MVP

- **项目核心：** 解决传统人工测试效率低、覆盖率差的问题。
    
- **MVP：** 一个复杂的 3D 地图，Bot 能在无人干预的情况下，自主发现地图中所有预设的“逻辑漏洞”（如穿模点、死胡同、触发失败的机关），并自动记录 Bug 发生的坐标和视频。
    

### 2. 实习里程碑 (35天)

|**阶段**|**任务目标**|**核心产出**|
|---|---|---|
|**W1: 测试场景构建**|建立包含多种物理 Bug（穿模、掉落、死循环）的 Unity 测试环境。|带有“已知缺陷”的测试场|
|**W2: 好奇心算法集成**|集成 ML-Agents 的 RND（Random Network Distillation）算法，赋予 Bot 探索欲望。|具有自主探索能力的 Bot|
|**W3: 异常检测逻辑**|编写底层逻辑，当 Bot 状态异常（速度过快、跌落世界、逻辑卡死）时自动记录。|自动 Bug 抓取系统|
|**W4: 覆盖率优化**|优化算法，使 Bot 能够在最短时间内走遍地图的每一个角落。|探索热点图 (Heatmap)|
|**W5: 报告系统**|开发一个 Web 端或 Unity 内的可视化工具，展示 Bot 发现的所有问题。|自动化测试报告生成器|

### 3. 任务职责分担

- 实习生
    
    - 运用 [QA 知识] 定义 Bug 判定标准。
        
    - 负责 Unity 环境与 Python RL 模型的通讯维护。

### 4. AI 逻辑架构 (Logic Prompts)

- **Observation (AI 看到什么):** "当前的视觉帧画面、我的三维坐标、我过去 5 分钟去过的位置历史。"
    
- **Action (AI 尝试动作):** "尝试向从未去过的坐标点移动；尝试跳向那些看起来‘不寻常’的碰撞体。"
    
- **Reward (AI 的目标):** "如果我到达了一个全新的视觉场景，+5；如果我发现了一个系统从未定义的异常状态（如坐标超出边界），给予最高奖励（+100）并记录当前上下文。"

使用unity而不是直接上专业的NVIDIA Isaac Gym：
- **验证可行性**：通过 Unity 快速验证“Sphero 数据预测拦截”这个逻辑是否行得通。如果模型在虚拟环境都接不住球，那在 NVIDIA 复杂的环境下更难。
    
- **数据中台意义**：以后你们可以把 Unity 作为**数据可视化工具**。即便算法是在 NVIDIA 里练的，也可以推送到 Unity 里给客户看 Demo（因为 Unity 渲染得更好看）。

使用 **ML-Agents Python API**，让实习生像写 **OpenAI Gym** 代码一样去操控 Unity（baseline可以使用mlagents-learn内置的算法来跑，但之后可以自己实现PPO来改进）：
- **回避了环境配置的坑：** NVIDIA Isaac Gym 对显卡驱动、系统版本要求极苛刻，实习生可能卡在安装上。Unity 则是“开箱即用”。
    
- **保留了算法的深度：** 他必须亲自处理 Observation 的处理和 Reward 的计算，这比单纯玩游戏 Mod 要硬核得多。
    
- **作品集含金量：** 如果他简历上写“我用 Python API 驱动 Unity 实现了机械臂拦截”，这比“我点了一下开始训练”要专业十倍。

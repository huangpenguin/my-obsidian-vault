# 其他操作

## ✅ 一、`git commit --amend` 的用法与场景

### ✅ 1. 修改提交信息（message）：

```bash

git commit --amend
# 会打开编辑器，修改提交信息
```

或直接在命令中指定新信息（避免打开编辑器）：

```bash

git commit --amend -m "New commit message"
```

### ✅ 2. 忘记添加文件了？可以补上再提交：

```bash
git add missed_file.py
git commit --amend
```

→ 会把新加入的文件合并到上次提交中。

> ⚠️ 注意：如果这个提交已经 push 过了，需要强推才能更新远端：
> 

```bash
git push origin main --force
```

因为会改动hash值，所以确定还没push的时候可以用，务必确保不会影响他人协作

[amend局限性](amend%E5%B1%80%E9%99%90%E6%80%A7.md)

## ✅ 二、`git rebase` 的用法与场景

### 📌 常见用法：

### 🔄 1. 变基到主分支（把当前分支的基础变成最新的主分支）：

```bash

git checkout feature-branch
git fetch origin
git rebase origin/main

```

→ 相比 `merge`，`rebase` 会让提交历史更清晰。

### ✍️ 2. 交互式变基（修改多个历史提交）：

```bash

git rebase -i HEAD~3

```

→ 对最近 3 次提交进行交互式修改。

你会看到：

```

pick e3a1b35 fix bug
pick 7ac9a67 update readme
pick f44d1bc add unit test

```

你可以将某行改为：

```

reword 7ac9a67 update readme

```

→ 这会让你修改这条提交的 message

你还可以：

- `pick`：保留
- `reword`：修改提交信息
- `edit`：修改提交内容
- `squash`：合并多条提交为一条
- `drop`：删除提交

> ⚠️ rebase 会重写提交历史，同样，如果已经 push 到远端，也需要 --force
>

## ✅ 总结对比表：

| 功能 | `git commit --amend` | `git rebase -i` |
| --- | --- | --- |
| 修改最近一次提交信息 | ✅ 支持 | ✅ 支持（reword） |
| 修改最近一次提交的内容 | ✅ 支持（先 `add` 再 amend） | ✅ 支持（edit） |
| 修改多条历史提交 | ❌ 不支持 | ✅ 支持（HEAD~N） |
| 合并提交（squash） | ❌ | ✅ 支持 |
| 删除历史提交 | ❌ | ✅ 支持（drop） |
| 改变提交顺序 | ❌ | ✅ 支持（调换行） |

## 🔧 一、与历史提交修改相关的指令

| 命令 | 功能 | 常见用途 |
| --- | --- | --- |
| `git commit --amend` | 修改最近一次提交 | 改 message 或补内容 |
| `git rebase -i HEAD~N` | 修改历史多个提交 | 改 message、squash、多条合并 |
| `git rebase --continue` | 在中断的 rebase 中继续 | 比如 `edit` 后修改完内容用这个继续 |
| `git rebase --abort` | 取消当前 rebase 操作 | 失败或后悔时回退 |
| `git rebase --skip` | 跳过当前出错的提交 | 一般在冲突但不需要那条提交时用 |
| `git reset` | 重置当前 HEAD | 回退提交或暂存内容 |
| `git revert` | 生成“撤销”提交 | 安全撤销某条 commit（不改历史） |

---

## 🪓 二、`git reset` 相关（**慎用**，会改变历史）

| 命令 | 功能 | 说明 |
| --- | --- | --- |
| `git reset --soft HEAD~1` | 回退提交但保留修改 | 修改提交时常用 |
| `git reset --mixed HEAD~1` | 回退提交+撤掉暂存 | 常用于不想要那次 commit 了 |
| `git reset --hard HEAD~1` | 回退提交并清除内容 | **危险操作**，慎用 |
| `git reset <commit-hash>` | 回到某次提交状态 | 指定 commit 回退 |

### 示例：

```bash
bash
复制编辑
git reset --soft HEAD~2
# 会把最近两次提交取消，但代码仍保留在工作区（适合重新组织）

```

## 🧯 三、安全撤销的 `git revert`

```bash
bash
复制编辑
git revert <commit-hash>

```

- 创建一条“撤销前一条提交”的新提交（不会改历史）
- 适用于已经 push 的情况

## 🔍 四、查看历史和日志

| 命令 | 用途 |
| --- | --- |
| `git log` | 查看提交历史 |
| `git log --oneline` | 简洁历史 |
| `git log --graph` | 可视化分支合并图 |
| `git reflog` | 查看所有 HEAD 移动记录（就算 reset 过） |
| `git show <commit>` | 查看某次提交的改动详情 |
| `git blame <file>` | 查看每一行是谁何时提交的 |

## 🧪 五、其他相关命令

| 命令 | 功能 |
| --- | --- |
| `git cherry-pick <commit>` | 把某条提交复制过来 |
| `git stash` / `stash pop` | 临时保存当前改动 |
| `git clean -fd` | 删除未追踪的文件和目录 |

## 🔁 六、常见使用场景一览

| 场景 | 推荐指令 |
| --- | --- |
| 改最后一次 commit 的 message | `git commit --amend -m "new message"` |
| 补文件到上一次 commit | `git add file && git commit --amend` |
| 合并最近 3 次提交 | `git rebase -i HEAD~3` + squash |
| 回退到 2 次提交之前 | `git reset --soft HEAD~2` |
| 撤销 push 后的 commit | `git reset --hard` + `git push --force` |
| 只回滚某条提交 | `git revert <commit>` |
| 复制某条提交到当前分支 | `git cherry-pick <commit>` |
